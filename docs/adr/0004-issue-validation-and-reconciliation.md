# ADR 0004：Issue 输入校验与写入结果对账

日期：2026-11-04。状态：已接受，限于 M0 受控验证约束和后续实现契约；原始上游差异仍需 M0-S04 汇总取舍，不表示 Issue 产品或整个 M0 验收通过。

## 原因与证据

Gitea 28.2.0 的[Issue 实测](../records/2026-11-04-m0-issue-validation.md)已覆盖公开 API 主路径、普通用户权限、资源删除及真实响应丢失。最终批次保留 12 条 gap：非法输入可能被忽略或转换，无效筛选可能返回更宽结果，部分错误返回 500，复合编辑失败后标题已经改变。读者角色可以创建自己的 Issue，但不能据此推导分类管理权限。

不能把 HTTP 200 / 201、正确 scope、目录中存在对象或某个失败状态码单独当作整个操作成功 / 无副作用的证明；也不能通过管理员凭据、私有接口或 Gitea 数据库修复验证结果。

## 决定

1. **输入按当前仓库验证。** 标签 / 里程碑使用真正整数 ID，拒绝布尔、小数、重复及未知 ID；负责人使用当前允许目录中的规范用户名。目录来自当前上游 API，不保存另一套 Issue 权威数据。本批个人仓库不覆盖组织继承标签或组织自定义单元权限，不能将本批集合直接推广为所有发行组合的权限模型。
2. **目录成员资格与操作授权分开。** 合法关联对象不等于当前用户有权分配它；`issue_write` scope 不等于仓库写者，更不等于仓库管理员。普通读者可创建自己的正文 Issue、不能编辑他人的 Issue 或管理分类；普通写者也不能直接删除 Issue。后续产品须核实具体操作权限，权限无法确认时不附带管理字段，不以服务账号补足。不能从代码写权限简单推导 Issue 单元权限。
3. **筛选不得默默退化。** 精确版本使用 `type=issues` 排除 PR，负责人筛选字段为 `assigned_by`；标签名、里程碑 ID / 名称按已验证协议映射。失效 / 不属于目标仓库的约束应使请求明确失效，不能去掉约束后展示更宽列表。上游原始无效筛选的 200 和实际结果继续保留；空结果、拒绝和无效输入不是同一状态。
4. **正文使用版本，但不承诺整个 PATCH 原子性。** 回读 `content_version`，提交已加载的版本；本批验证旧版本 409 且未覆盖并发正文，再回读新版本后才提交。该字段不能作为标题、分类、状态等全部字段共享原子版本的证明。固定 OpenAPI 的编辑响应列表没有列出实际 409，后续自有契约须明确冲突，不以只识别 201 的生成结果吞掉它。
5. **错误后也要回读。** 复合编辑可能在 500 前已写标题。失败、冲突和超时后查询当前资源并比较请求字段，明确未确认、部分完成、当前已观察到目标结果等状态，保留草稿及原始原因；不能把错误码当成自动回滚证明，不盲重放写请求或用删除上游对象模拟回滚。关联前检不能消除检查与写入之间的变化，因此结果复核仍是必要边界。
6. **创建超时不重试。** M0 使用仅属于合成数据的标题 / 正文标记及作者，在固定仓库分页查找并回读详情；唯一匹配只能证明本批观察到的结果。零条、多条、详情变化、拒绝或查询失败均不自动再次 POST，不选择“最新 Issue”。这不是 Gitea 原生幂等键，也不是任意生产请求都能可靠关联的承诺。

`m0_issues.py` 的关联前检、分页及对账函数和真实用例仅用于 M0；`m0_issue_faults.py` 只注入本任务固定端点的响应丢失。Go 服务、前端草稿 / 部分完成交互、正式授权检查与持久化请求关联尚未实现，需在 M1 / M2 分别验收。

## 差异处理与停止线

| 原始上游行为 | 本批处理 | 保留限制 |
| --- | --- | --- |
| 非法标签 200 忽略；小数标签值 200 且改变关联 | 联网前拒绝非法 / 非整数值，操作后回读 | 不表示任意上游客户端都受限 |
| 非法里程碑 / 不存在负责人返回 500 | 先核对目录；保留状态码和写后结果 | 不伪装为正确的 4xx，也不自动重试 |
| 非法关联创建 201，但分类丢失；读者提交分类字段被忽略 | 结果必须与明确请求字段对照，不能报告整个请求成功 | 创建的 Issue 仍是已发生副作用，不能因字段缺失再创建一条 |
| 无效标签 / 里程碑筛选返回更宽列表 | 明确拒绝失效约束，不退回无筛选状态 | 不证明上游任意筛选满足 GitHub 语义 |
| 复合编辑 500 后标题改变 | 查询并呈现部分完成，停止自动写入恢复 | 没有证明完整事务 / 回滚或任意并发正确性 |

保留原始请求轨迹、源码 / 配置摘要和非零退出码；不关闭整个 M0-03、ISSUE-01、COMP 或 M0。上游版本、字段、scope、资源权限或重试方案变化时，重跑相应正向及失败契约。是否接受这些受控边界、调整承诺或选择其他公开接口路径，纳入 M0-S04 既有缺口评审；不因本批记录存在自动进入 M1。
