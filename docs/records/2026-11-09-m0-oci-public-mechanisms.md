## M0-G26 · Digest 强制保留

- **已有实测。** `overwriting_last_tag_original_digest_retention` 记录同一 Tag 被覆盖后，旧 Manifest 按 Digest 读取返回 404。独立删除用例中，Registry 删除 Manifest 返回 202，原 Tag / Digest 随后返回 404。早期中断批中旧 layer 仍可读，说明至少该次 Manifest 失联与物理 Blob 回收可分开观察。[原始取证](2026-11-04-m0-oci-validation.md#保留的四项差异)
- **清理配置。** 所有者可在原生设置页按包类型配置和预览规则，Container 规则按 owner 匹配。固定源码先按创建时间与保留数量筛选，再应用保留 / 删除模式和年龄条件。保留模式匹配版本或 `包名/版本`，因此匹配的是实际版本条目。清理规则会跳过 `latest`，也会跳过仍被其他 Manifest 引用的 Digest 版本。后者是清理阶段的引用检查，尚需实测覆盖和清理后的可拉取性。[公开清理说明](https://docs.gitea.com/usage/packages/storage/#cleanup-rules) · [固定清理实现](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/services/packages/cleanup/cleanup.go#L35-L84) · [Container 跳过条件](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/services/packages/container/cleanup.go#L82-L107)
- **覆盖与删除。** Manifest PUT 遇到重复版本时删除原版本关联，再写入新版本。OCI 公开路由按包权限放行 Manifest PUT、按 Tag / Digest 的 Manifest DELETE 及 Blob DELETE。Packages REST 另允许有包写权限的调用方删除单版本或整个包，原生包页面也有删除入口。Git 仓库的 `tag_protections` 管 Git 引用。上述 Registry / Packages 写入和删除路径没有接入包清理保留模式。[版本覆盖](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/routers/api/packages/container/manifest.go#L269-L294) · [OCI 路由](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/routers/api/packages/api.go#L564-L584) · [Packages REST 路由](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/routers/api/v1/api.go#L1752-L1772) · [包删除说明](https://docs.gitea.com/usage/packages/overview/#delete-a-package) · [Git Tag 保护](https://docs.gitea.com/usage/access-control/protected-tags/)
- **Blob 回收。** `cron.cleanup_packages` 执行包版本规则，再清理过期的未引用包数据，默认 `OLDER_THAN = 24h`。调整任务或年龄可以改变清理行为，Registry 写入和显式删除仍各自生效，Manifest 引用可能先于 Blob 物理回收消失。[固定配置](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/custom/conf/app.example.ini#L2377-L2391) · [清理执行与回收](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/services/packages/cleanup/cleanup.go#L167-L208)

## M0-G27 · PAT 删除与已签发 JWT

- **已有实测。** `deleted_pat_does_not_imply_cached_registry_token_revoked` 中，删除单个普通用户 PAT 得到 204，原 PAT 再换取 Registry JWT 返回 401，先前 JWT 直接读仍为 200、开启上传仍为 202。单独验证的团队降权、移出私有组织及禁用账号会限制旧 JWT 的相应访问。24 小时仅有声明，未等待真实到期。[原始取证](2026-11-04-m0-oci-validation.md#保留的四项差异)
- **签发与鉴权。** `GET /v2/token` 使用当前账号与包 scope 签发 JWT。普通用户的 JWT 携带用户 ID 和 scope，签发使用 HS256、通用签名密钥和固定 24 小时 `exp`，未带来源 PAT ID 或已赋值的 JWT ID。校验读取 JWT 中的 scope，重新读取用户并按当前包权限判定。该请求链未查询来源 PAT 或 Registry JWT 撤销记录。[签发入口](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/routers/api/packages/container/container.go#L152-L187) · [JWT 签发及解析](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/services/packages/auth.go#L21-L88) · [账号回读](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/routers/api/packages/auth.go#L26-L58) · [包权限](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/services/context/package.go#L112-L165)
- **公开路径与配置。** 固定 OpenAPI 暴露 `DELETE /api/v1/users/{username}/tokens/{token}`，处理器删除指定账号的 PAT。Registry 的 `/v2/token` 路由提供 GET 签发，POST 为未实现入口。固定 OpenAPI、Registry 路由、`[packages]` 配置和实际校验路径均未发现单 JWT / 单 PAT 派生 JWT 的即时撤销机制，也未发现该 Registry JWT 的专用 TTL 配置。`[oauth2]` 的 access / refresh TTL 属于另一条认证路径。[PAT 删除](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/routers/api/v1/user/app.go#L166-L232) · [Registry Token 路由](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/routers/api/packages/api.go#L537-L563) · [固定包配置](https://github.com/go-gitea/gitea/blob/829b49c1ae96015e345f9d2a0eb1ea7acd5f31e1/modules/setting/packages.go#L14-L64)
