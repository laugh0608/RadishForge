# 部署、升级与恢复

状态：规划；当前没有 Dockerfile、Compose、启动脚本、镜像、端口占用或部署实例。

## 参考与适配

参考 Radish 的四类环境、预构建镜像、外部 TLS、固定版本及迁移编排。沿用运维原则，不照搬其 .NET 技术栈、六数据库、Redis 或证书默认值。

| 环境 | 规划形态 |
| --- | --- |
| 开发 | Go 与 Vite 在宿主直接运行，隔离 PostgreSQL / Gitea 测试实例，使用合成数据 |
| 本地容器验证 | 可选 Compose build，核对实际镜像与网络 / 挂载，独立目录与端口 |
| 测试部署 | 拉预构建固定镜像，外部反代 TLS、容器内受限 HTTP，与生产拓扑接近 |
| 生产部署 | 拉正式镜像和 Digest，维护窗口、持久化数据、明确迁移及恢复流程 |

建议首版验收 Linux x86_64 + Docker Compose plugin，以 `docker compose` 命令及精确版本行为验收；不把旧的 v2 主版本建议当作永久限制。2026-11-01 的[M0-S01 候选](../planning/m0-s01-baseline.md)为 Engine 29.9.2 / Compose 5.6.1，尚未安装或运行。arm64 作为需要实际构建与恢复验证的第二目标，不凭多架构标签宣称可用。Docker / Compose / PostgreSQL / Go / Node 的支持组合依据 M0 证据最终冻结。

## 容器与配置

自有服务规划为 Web 静态镜像与 Go 服务镜像；迁移以同一固定 Go 镜像的一次性子命令执行，后续有独立构建需求再拆镜像。Gitea、PostgreSQL、反代和 Runner 保留上游独立版本。API / worker 可先同进程，按实际负载再分进程。

平台与执行环境分网：平台服务不挂载 Docker socket；构建 Runner 与生产 CD Runner 分主机 / VM 或等价信任隔离，不能仅以 label 代替隔离。Registry / Git 对外入口、SSH 端口、回调和 Web origin 分别配置。

同一前端镜像加载运行时公开配置；服务端秘密通过受限文件或秘密系统注入，不进入前端、镜像层或日志。参考配置只用占位值，正式安装生成秘密；更换域名同步 OIDC 回调、Gitea ROOT_URL、Git clone / Registry 地址与前端公开入口。

## 数据

- RadishForge 与 Gitea 使用独立数据库和数据库身份；可共享 PostgreSQL 实例，不跨库直接读写。
- 持久化 Gitea 仓库、LFS、Packages、附件及配置；按所选存储后端包含对象存储。
- 自有库持久化授权绑定、清单、部署、事件和审计；加密主密钥独立备份，丢失不能靠数据库恢复。
- Runner 注册信息、部署凭据、TLS / OIDC 配置另有受控保管；缓存可丢弃，产品事实不可丢弃。
- 日志、备份和运行数据分目录，备份不只留在同一磁盘；定义访问与保留策略后实施。

## 安装与升级顺序

首次空环境：配置预检 → 创建基础设施 → 显式迁移自有库 → 按上游要求初始化 Gitea → 注册 OIDC / OAuth 与 Runner → 启动工作台 → 健康及完整主路径检查。支持通过独立运维入口完成，不要求先运行 RadishForge 的 CD。

既有环境升级：

1. 固定发行清单、自有与上游镜像 Digest、数据库兼容范围；提前拉取并确认磁盘与备份位置。
2. 暂停新部署和发布，排空或明确中止任务；停止全部会改动被备份数据的写入者，记录维护水位。
3. 同批备份自有库、Gitea 库、仓库、制品、附件及必要配置；生成清单、校验和，并记录密钥备份引用。
4. 显式执行自有 migration apply，再独立 verify；应用启动不得自动修补自有 schema。
5. Gitea 的迁移按精确版本官方升级流程在隔离条件下执行，不擅改其机制，也不让自有迁移工具改 Gitea 库。
6. 启动目标应用，验证健康、登录、Git / Issue、镜像与查询，再逐步恢复 Runner 和写入口。
7. 记录实际版本、备份批次、迁移结果、主路径和残留问题，成功后结束维护。

尽量将底座升级与自有业务 / schema 升级分批，减少失败原因。若无法完整停止写入，必须设计并验证一致性快照方案，不能把顺序在线 dump 宣称为跨系统一致备份。

## 失败与恢复

预检失败不影响当前实例。备份失败且迁移尚未开始时，核对现场后恢复旧写入者。迁移开始后失败保持维护状态，保留现场；不能自动启动旧应用连接可能不兼容的库。

优先评估前滚。必须恢复时，在隔离目标校验同批备份、密钥、镜像与 schema，重建后复核 Git 对象、镜像 Digest、Issue、Release 和部署记录，再按授权切换。只验证 dump 非空或能列目录不算恢复通过。

M6 演练并记录实际恢复用时、可接受丢失窗口、存储规模与宿主配置；当前不承诺无测量的 RPO / RTO 数字。镜像回退与数据库恢复分别记录。具体通过条件见[验收](../planning/acceptance.md)。
