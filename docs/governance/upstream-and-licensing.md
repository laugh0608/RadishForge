# 上游维护与许可边界

## 集成原则

首选 Gitea 作为独立服务，React / Go 扩展通过公开 API、OAuth/OIDC、Webhook、Git 与 OCI 协议连接。首版零核心补丁是工程目标，不承诺所有未来需求无需修改底座。

扩展顺序：配置 → 官方自定义入口 → 公开 API / Webhook → 上游贡献 → 有必要且经评估的小补丁。不得直接读写底座数据库、调用其私有前端接口或把 Gitea 内部 Go 模块嵌入自有业务服务。

品牌层限制在自定义 Logo、语义主题与导航入口，避免覆盖整页模板、注入 DOM 操作或 iframe 包装整个产品。

## 来源与升级

M0 确认精确 Gitea / Runner 版本、提交、镜像 Digest、OpenAPI 摘要、许可证与已验证兼容范围。2026-10-29 静态参考版本为 Gitea v28.2.0，不是已部署版本；Runner 版本尚未冻结，不能由 Gitea 版本推断。

RadishForge 自有源码与上游运行镜像分离维护，不复制整个上游仓库。若未来确需补丁，再建立单独的底座维护分支或仓库，保留原始历史、上游 remote、补丁目的、测试、负责人和退出条件。

升级独立于普通业务提交：阅读变更 → 比较接口 → 隔离恢复副本 → 执行契约与完整交付回归 → 验证迁移与恢复 → 记录兼容组合 → 获授权后发行和部署。不能只更新镜像标签后宣称兼容。

## 许可

Gitea v28.2.0 根许可为 MIT；Forgejo 官方说明 v9 及以后为 GPLv3+。第三方依赖、镜像、主题、图标与 Action 另有来源，不能凭根许可免除核查。

本项目尚未选择自有代码最终许可证。参考 RadishInk 的分范围来源管理方式，但不擅自复制其自定义许可，也不宣称整个产品为开源或闭源。若未来分发修改的 Forgejo，必须履行适用 GPL 对应源码等义务，不能以独立进程为理由笼统豁免衍生作品判断。

固定保留上游声明、第三方清单及构建来源；自有内容与上游资产分别说明。正式发行前核对实际源码包、前端包、镜像和 Action 镜像，商标不随代码许可自动转移。
