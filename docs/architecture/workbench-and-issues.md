# 工作台与 Issue

状态：产品与页面设计；已有[M0 Issue 上游契约证据](../records/2026-11-04-m0-issue-validation.md)，工作台尚未实现。Web-first，PC、窄屏和键盘均纳入验收。

## 导航与页面

```text
总览

  概览 / 代码 / Issue / PR / 构建 / 镜像与制品 / 版本发布 / 环境与部署 / 设置

```

项目概览围绕“提交 → 构建 → 制品 → Release → 部署”显示可追溯关联。Issue / PR 链接保留仓库上下文，不把数字编号当全局 ID。复杂 PR 评审、冲突处理和实时日志提供原生入口，并保持当前项目与底座来源可辨认。

## Issue 首版契约

| 操作 | 输入与状态 | 验收重点 |
| --- | --- | --- |
| 列表 / 筛选 | 仓库、开关状态、关键词、标签、负责人、里程碑、分页 | 空态、翻页、无权限；不把 PR 混成普通 Issue |
| 创建 | 标题、正文、合法标签 / 负责人 / 里程碑 | 必填校验、权限、请求中禁重入、超时未知结果 |
| 编辑 | 已加载正文 `content_version`、标题与正文 | 过期版本冲突后回读；不将正文版本视为所有字段共享原子版本；无适用条件更新能力时明确覆盖风险 |
| 评论 | Markdown 正文 | 转义与 XSS 防护、失败保留草稿、重复提交处理 |
| 开关状态 | 当前状态、期望状态 | 失权、已被他人修改、失败回读 |
| 分配与分类 | 可用人员、标签和里程碑 ID | 只能选当前仓库允许对象，不传任意外部 ID |

Issue 正文、评论、状态和分类的权威事实归 Gitea。工作台可保存短期表单草稿及缓存，不建立第二套 Issue 存储或独立编号体系。负责人和标签的管理动作与分配动作权限分开核对。

创建 / 评论超时不得自动反复提交。优先查验请求关联与上游结果；若无法可靠定位，显示“结果待确认”和刷新入口，由用户确认后重试。乐观 UI 只用于可回滚的展示，不提前宣称写入成功。

## Gitea 28.2.0 上游验证边界

2026-11-04 的[M0-S03 切片](../records/2026-11-04-m0-issue-validation.md)已取得列表 / 筛选 / 分页排除 PR、编辑 / 关闭 / 重开、标签 / 负责人 / 里程碑增删和管理操作、真实用户权限、资源删除与响应丢失的证据；最终批次保留 12 条原始差异，不等于整个 ISSUE-01 或工作台可用。

- 显式请求 `type=issues`；负责人筛选使用 `assigned_by`。无效标签 / 里程碑约束可能返回更宽列表，不能去掉约束后默认展示成功。候选对象与筛选值来自目标仓库的有效目录，失效约束明确处理。
- 正文编辑传已回读的 `content_version`，旧版本 409 后回读当前状态并保留草稿。复合编辑可能在 500 前已修改标题，失败 / 冲突 / 超时都不能当作整体回滚；不能宣称完整 PATCH 原子性。
- 标签 / 里程碑 ID 严格为整数并核对归属；目录成员资格不代表当前用户有分配权限。普通读者可创建自己的 Issue，但管理字段可能被上游静默忽略，201 不等于全部请求字段已处理。写后逐项对照实际结果，不借管理员或服务账号补足权限。
- 超时后的唯一匹配、零匹配、多匹配和查询失败分别处理；本批合成标记不是生产幂等键。正式请求关联、草稿 / 部分完成交互和缓存撤销仍需在 M1 / M2 实现后验收。

受控前检、权限与结果的分界见[ADR 0004](../adr/0004-issue-validation-and-reconciliation.md)。原始差异与组织继承标签 / 自定义单元权限等未覆盖面继续进入 M0-S04 评审，不以单一 scope 或本批个人仓库成功外推。

## 通用交互

每页定义 loading、empty、ready、stale、forbidden、not-found、error。403 / 404 是否统一隐藏由接口策略决定；页面不能因缓存泄漏资源名。长仓库名、日志和表格可滚动，窄屏保留主要操作，危险动作有明确对象和结果。

页面焦点、标签、键盘与屏幕阅读提示可用；错误不只靠颜色。Markdown 和日志使用审查过的渲染 / 清洗链，秘密掩码是辅助措施，原始日志访问仍受权限约束。

前端公共配置从运行时加载，同一静态镜像用于不同安装；相对 API 地址优先，不把构建环境的客户域名编译进包。
