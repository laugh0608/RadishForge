# 验收矩阵

DOC-01、GOV-01 与 GOV-04 已有本地文档 / 治理 / Git 证据；GOV-02 已有远端配置读回，行为验收未完成；GOV-03 与业务项尚未通过。范围以[产品规划](../product-plan.md)为准，任务与能力专题的对应见[专题索引](topics.md)。

| ID | 输入 / 操作 | 通过标准与失败边界 | 证据层级 |
| --- | --- | --- | --- |
| DOC-01 | 检查指定项目目录、Markdown、根协作入口、任务与来源 | 规划及治理范围清楚；文件链接可达；AGENTS / CLAUDE 除标题一致；整体规划、能力专题、近期子专题、阶段 / 任务 / 验收可互相定位；远期不堆空文件；不冒充产品实现 | 本地文档 |
| GOV-01 | 运行本地治理检查与故障回归，审阅基础文件和模板 | 格式、链接、入口同步、JSON 及政策契约通过；缺文件、入口漂移、坏链接、错误门禁等负例拒绝；Git 和远端实际启用状态如实记录 | 本地治理 |
| GOV-04 | 获授权初始化本地 Git，以现有身份完成首个提交并建立 master / dev | 一个无父共同基线提交；作者与提交者沿用用户身份；两分支同 SHA，HEAD 位于 dev；暂存区与工作树无遗留，未创建 remote / upstream 或推送 | 本地 Git |
| GOV-02 | 获授权初始化 Git、建立远端与基础保护 | 唯一共同基线、master / dev、用户身份、实际设置与有效规则可追溯；PR、历史保护、合并方式通过真实验收并记录限制 | 真实 Git / 远端 |
| GOV-03 | 真实 CI 接入并升级主线 required check | Candidate Quality 成功与故障传播、正确来源和当前 SHA 验证后更新同一规则；strict / context 读回一致，主线合并后回流 | 真实 CI / 远端 |
| BASE-01 | 固定 Gitea / Runner 组合，测试各公开接口 | 记录版本、Digest、OpenAPI 来源；身份、Issue、Actions、镜像、Release 最小操作真实可行；缺口有决定 | 真实上游 |
| BASE-02 | 启动自有最小服务与前端，连接隔离库 | OpenAPI 客户端与服务一致；配置错误明确失败；迁移独立执行，API 启动不自动改 schema | 集成 |
| IAM-01 | OIDC 成功、重放、过期、错误签名 / issuer / audience | 标准授权码 + PKCE；非法回调拒绝；用户会话与浏览器 Token 暴露检查通过；登出边界准确 | IdP + 浏览器 |
| IAM-02 | 两个用户、两个 issuer 同邮箱、绑错账号、撤权 / 解绑 | 不自动合并；写入用真实用户权限；缓存及后台作业不越权；秘密不进入前端 / 日志 | 真实权限 |
| REPO-01 | 关联仓库、重命名、转移、删除、私有 / 无权访问 | 稳定 ID 保持关联；失联明确；文件 / 分支 / Tag / 提交展示正确，原生 PR 链接上下文准确 | 上游 + UI |
| ISSUE-01 | 非管理员创建、编辑、评论、关闭 / 重开、分配标签 / 人员 / 里程碑 | 重读 Gitea 结果一致；分页不混 PR；越权拒绝；超时不盲重试；并发变更可见 | 上游 + UI |
| UI-01 | PC、窄屏、键盘、长内容、空态、失权、断网 | 主操作可到达；焦点正确；草稿不因普通失败丢失；错误与过期状态可见；Markdown 不执行脚本 | 浏览器 |
| EVENT-01 | 重复 / 乱序 / 丢失事件、非法签名、处理中崩溃 | 验签后持久化再应答；去重；API 对账恢复；终态不回退；租约和失败队列可诊断 | 故障注入 + 上游 |
| BUILD-01 | push / Tag 与手动触发，取消、重跑、日志下载 | 一次事件不重复触发；run / attempt 关联准确；无 Runner、失败、取消与未知结果分别展示；原生实时日志入口可用 | 真实 Runner |
| ART-01 | 多组件镜像推拉、私有组织、仓库关联、删除制品 | 服务端确认 Digest / 来源；无权用户直接 pull 也拒绝；组织包边界如实呈现；缺失阻止发布 | OCI 客户端 + 上游 |
| COMP-01 | 固定首批原始 GitHub 工作流样例 | 每项标直接兼容 / 配置 / 适配 / 不支持，并记录 diff、版本和证据；没有“默认全部兼容” | 双端样例 / 对照 |
| COMP-02 | permissions / environment / concurrency、fork PR、秘密访问负向样例 | 安全语义生效或明确拒绝；静默忽略视为失败；受控模板补足不能冒充任意 YAML 兼容 | 真实执行与权限 |
| COMP-03 | 固定 REST API version、gh / Octokit 指定调用、Webhook 样例 | 已承诺子集路径 / 字段 / 分页 / 状态码 / Token / HMAC 行为符合对照；不支持项准确返回；跨用户隔离 | 客户端契约 |
| REL-01 | 五组件构建、缺一组件、Tag 移动、附件损坏 | 完整且来源一致才发布；保存冻结清单与校验和；缺失或漂移明确阻断 | 真实发布链路 |
| REL-02 | 双击、重复事件、超时、部分上传、服务重启 | 同版本不产生重复发布；已发生副作用可查询；未知结果先对账；恢复不删无归属数据 | 故障注入 + 上游 |
| DEP-01 | 指定清单部署，两个请求竞争环境，Runner 掉线 | 重新授权、固定 ref、请求与 run 准确关联；同环境不会并发改写；旧执行状态未知时不盲解锁 | CD Runner |
| DEP-02 | 测试晋级生产、健康失败、迁移失败、部署上一版本 | 同一 Digest；生产有显式操作；成功需健康证据；迁移后不自动回旧镜像；回退形成新记录 | 隔离目标环境 |
| SEC-01 | 外部 PR、恶意工作流、任意目标地址和镜像坐标 | CI 无生产秘密；CD 只执行受控意图；平台无 Docker socket；SSRF / XSS / CSRF 与对象越权拒绝 | 负向集成 |
| OPS-01 | 干净宿主安装，更换公开域名 / IdP 配置 | 只拉固定镜像；同一前端包支持运行时配置；Git / SSH / OCI / 回调正确；不依赖兄弟项目 | 干净安装 |
| OPS-02 | 停写同批备份、迁移中失败、隔离恢复 | 库、仓库、制品、附件、密钥可恢复；实际读 Issue / clone / pull / 清单一致；记录恢复用时与丢失窗口 | 实际恢复 |
| UPG-01 | 从已支持底座 / Runner 升级至候选组合 | 接口差异审查、迁移与恢复检查、关键权限及 E2E 回归通过；旧组合记录保留 | 隔离升级 |
| LIC-01 | 检查实际源码、Web 包、镜像、Action 及声明 | 精确来源 / 许可 / 修改范围 / SBOM 可追溯；未决依赖有处理；所有者确定自有许可后再正式分发 | 交付物检查 |
| E2E-01 | 登录 → Issue → 提交 / Tag → 五镜像 → Release → 测试 → 生产 → 恢复演练 | 全链路能定位源码、run、Digest、清单、用户与部署结果；真实失败行为可解释；文档与安装一致 | 完整用户场景 |

阶段晋级要求本阶段相关项通过，或有明确批准且不破坏关键权限 / 数据正确性的范围调整；不能用“以后再补”关闭关键安全和恢复缺口。没有真实生产环境时只记录隔离环境验收，不宣称生产上线。

M0 的 BASE-01 需要真实上游最小操作，不因候选版本表或计划存在而通过；IAM-01 / IAM-02 在 M0 只取得上游协议和授权部分证据，自有会话、绑定交互、Token 存储及后台撤权需在 M1 继续验收；COMP-01 在 M0 固定样例与差异基线，未运行项保持待验证，M3 完成首批兼容验收。细分范围见[M0 子专题计划](m0-validation.md)。
